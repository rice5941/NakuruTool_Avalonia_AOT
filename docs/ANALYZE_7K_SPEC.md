# 7K 譜面解析 仕様

NakuruTool の beatmap一覧に、7K 譜面の **Prism（基準96.5%）** と **段位推定** を表示する機能の仕様。
計算は Mania Tracker（mania-hub）を固定コミットで使う Rust ライブラリ `analyze_7k.dll`（`native/nakuru_7k_analyze/`）で行う。
上流との対応と出典は `native/nakuru_7k_analyze/UPSTREAM.md` を参照。

## 1. 範囲

- **対象**: osu!.db にある native 7K の譜面すべて（未プレイを含む）。
- **速度**: 等速（rate 1.0）だけ。DT / HT は解析しない。
- **スコア**: 使わない。プレイヤーのスキル集計・スコアごとの評価・ローカルランキングへの表示は行わない。
- **MinaCalc**: 同梱しない（7K は Prism で計算するため使われない。`vendor/leoblack-ett/` で差し替え）。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 基準Overall | 精度 96.5%（Prism の基準 goal）を出すのに必要な強さ＝譜面の難易度。Reg と LN の2つがある |
| Reg 基準Overall | Prism の通常モデルの Overall |
| LN 基準Overall | Prism の LN モデルの Overall（ln-skill 経由）。LN 譜面と判定されない譜面は値なし（測定不能） |
| 基準スキル値 | 6ジャンルの Prism 値（Overall × ジャンル比、LN の多い譜面の補正を含む）。huuugeosu と同じ値（huuugeosu の Jack は Jack / ChordJack の大きい方） |
| ジャンル傾向 | 難しさを決めている区間に、そのジャンルがどれだけ濃く含まれているか（0〜100、全ジャンル共通の物差し）。§4 |
| ジャンル濃度 | ジャンル傾向の内訳（%）。6ジャンルの合計が 100 になる。画面に出すのはこちら。§4 |
| 推定段位 | 段位エンジンの譜面段位（`raw_dan`）。Reg と LN の2つがある。プレイ精度による補正（Reg 96% / LN 95% の合格ライン）は使わない |
| 段位ジャンル | 段位推定の種類。Reg: Jack / Tech / Speed / Stream、LN: General / Tech / Inverse / Release |
| 主分類 | 段位エンジンが判定した譜面の主な分類（Regular / LN） |

## 3. Prism のジャンル

| 表示名 | Prism の値 |
|---|---|
| Chordstream | Jumpstream（Stream / JumpstreamOnly の大きい方） |
| Bracket | Handstream |
| Delay | Speed |
| Technical | Technical |
| Jack | JackSpeed（単押しの縦連） |
| ChordJack | ChordjackOnly（同時押しの縦連） |

Prism と huuugeosu は JackSpeed / ChordjackOnly の大きい方を Chordjack（huuugeosu の Jack）として1つにまとめるが、
NakuruTool は2つを分けて表示する（2026-11-15 の試行。キャッシュの版 `chart-2`・アダプタ版 4）。

LN はジャンル値を持たない（LN モデルは Overall だけを出す）。

## 4. ジャンル傾向とジャンル濃度

### 4.1 ジャンル傾向

Prism はジャンルごとに、区間の負荷に `0.6 + 0.4 × min(2, 区間内の割合 ÷ 基準割合)^指数` を掛けてから、
Overall と同じ精度の式で強さを解く。解は負荷に比例するので、

```
r = ジャンルの強さ ÷ Overall の強さ   （どちらも精度 96.5%、連打経路なし）
傾向 = clamp((r − 0.6) ÷ (R − 0.6), 0, 1) × 100,   R = 0.6 + 0.4 × 2^1.2 ≈ 1.519
```

- **全ジャンル共通の物差し**。R は全ジャンルの倍率の上限のうち最大のもの（Delay＝Speed、指数 1.2）。
- 1譜面の中でのジャンルの大小は、基準スキル値と必ず一致する（基準スキル値 = Overall × 強さ ÷ 最大の強さ。
  LN の多い譜面の補正も全ジャンルに同じ倍率を掛けるだけ）。
- どの区間にも含まれないジャンルは 0。100 になるのは、全区間が Delay で上限に達した譜面だけ。
- ジャンルごとに届く上限が違う（Prism の曲線の指数と基準割合がジャンルごとに違うため）。区間内の割合は 100% を超えないので、
  全区間がそのジャンルの譜面でも次の値で頭打ちになる。

  | ジャンル | Prism の値 | 基準割合 | 指数 | 上限 |
  |---|---|---|---|---|
  | Chordstream | Stream / JumpstreamOnly | 0.9765 / 0.625 | 0.625 / 0.5 | 44.2 / 55.1 |
  | Bracket | Handstream | 1.0 | 0.625 | 43.5 |
  | Delay | Speed | 0.5 | 1.2 | 100 |
  | Technical | Technical | 0.0922 | 0.45 | 59.5 |
  | Jack | JackSpeed | 0.18 | 0.96 | 84.7 |
  | ChordJack | ChordjackOnly | 0.45 | 0.5 | 61.6 |

- まとめる2つのジャンル（Chordstream）は大きい方。
- 合計は 100 にならない（Delay・Technical は他のジャンルに重ねて数えるため）。
- 難しさの値ではない（簡単な譜面でも Jack ばかりなら Jack は高い）。
- ネイティブ（`analyze_7k.dll`）が計算し、キャッシュに保存する（`gc`）。

### 4.2 ジャンル濃度（画面に出す値）

```
濃度(%) = そのジャンルの傾向 ÷ 6ジャンルの傾向の合計 × 100
```

- 6ジャンルの合計が 100 になる。Prism が各ジャンルに上乗せした負荷（r − 0.6）の内訳にあたる。
- 全ジャンルを同じ数で割るだけなので、1譜面の中での大小は傾向・基準スキル値と同じ。傾向のないジャンルは 0%。
- 傾向の強さは表さない（傾向がすべて 10 の譜面も、すべて 30 の譜面も各 20%）。
- 傾向がすべて 0 なら濃度もすべて 0（実データ 43,673 譜面には該当なし）。
- C# 側（`GenreValues.ToShares`）で、キャッシュの傾向から表示のたびに計算する（キャッシュの形式は変えない）。
- 画面の数値は整数に丸め、最大剰余方式で表示の合計をちょうど 100 にする（`GenreValues.ToRoundedShares`。
  切り捨てた後、端数の大きいジャンルから 1 ずつ足す。同じ端数なら表示順で先のジャンル）。

## 5. 段位推定

- 段位エンジン（dan-calc）を等速・譜面の OD で実行し、Regular / LN の `raw_dan`、主分類、対象判定（eligible）、縦連打（vibro）を得る。
- 段位ジャンルは huuugeosu の `mania_dan_buckets.py` を移植した `DanBuckets` で判定する（等速・OD 指定なしの配置分析から）。
  - LN: パターンスコア（lngeneral / ln、lntech、lninverse、lnrelease）が 0.5 以上、かつホールド比率 37.5% 以上。
  - Reg: クラスタの構成比とカテゴリ、配置の特徴量（riceShape）、delay などのスコアによる判定木。
- 表示は「段位名（数値）」（例: `9th Dan Mid/High (9.18)`）。LN 段位がない譜面は「測定不能」。
- 縦連打・対象外の譜面も値は表示し、⚠ を付ける。

## 6. 画面

### beatmap一覧

Prism 列と段位推定列は、ヘッダーの「解析結果を表示」ボタン（`IsAnalysisMode`）を押している間だけ表示する。

- 解析結果モード中は、履歴列とプレイ済み列を隠す（BPM・LN率は残す）。
- ローカルランキング表示とは排他（片方を ON にするともう片方は OFF）。どちらも永続化しない。
- 解析結果モード中だけ、ヘッダーに基準スキル値 / ジャンル濃度のラジオボタンを出す（既定は基準スキル値）。
- beatmap生成ページではボタンも2列も出さない（`ShowAnalyze7kColumns="False"`）。

| 列 | 内容 |
|---|---|
| Prism（基準96.5%） | 左: Reg 基準Overall、LN 基準Overall（なければ「測定不能」）。右: ジャンル濃度の六角形と凡例、または基準スキル値と LN の横棒（ヘッダーのラジオボタンで切替） |
| 段位推定 | Reg 推定段位と Jack / Tech / Speed / Stream、LN 推定段位（なければ「測定不能」）と General / Tech / Inverse / Release。有効なジャンルを強調、主分類に ★ |

- 右側はヘッダーのラジオボタン（基準スキル値 / ジャンル濃度。既定は基準スキル値）で切り替える（設定 `Analyze7kShowConcentration` に保存）。描画は `PrismGenreChart`。
  - **ジャンル濃度**: 六角形のレーダーチャートと凡例。
    - 頂点は 12 時から時計回りに表示順（Chordstream → Bracket → Delay → Technical → Jack → ChordJack）。
    - 外周が 50%（超えた分は外周で止める）。目盛りは外周と 25% の2重。5ジャンルだったときの実データでは各ジャンルの 90% 点が 26.6〜47.6% に収まっていた（§9.2）。
    - 形は半透明の青、頂点にジャンルの色の点（0% のジャンルは点なし）。傾向がすべて 0 の譜面は目盛りだけ。
    - 凡例は「● ジャンル名　濃度（%、整数）」。濃度の数値は6ジャンルの合計がちょうど 100 になる。
  - **基準スキル値**: 6ジャンルと LN の7本の横棒（huuugeosu の6軸の並び・色に ChordJack `#d4c04a` を足したもの。LN は `#c66f84`）。数値（小数1桁）も表示。
    - 7本並ぶので、行が狭いときは文字を少し小さくする（10.5 → 最小 8）。
    - LN の値は LN 基準Overall。測定不能なら棒なしで数値は「-」。
    - 満幅は Reg 基準Overall・LN 基準Overall・6ジャンルの値のうち最大のもの（LN 譜面では LN が Reg を超えることがあるため、7本を同じ物差しで比べる）。
- 解析中はヘッダーの下に進み具合の帯を出す（終わると消える）。
  - 「7K譜面を解析中」、プログレスバー、進捗率（切り捨て。終わるまで 100% にしない）、「解析済み / 対象 譜面」、残り時間の目安。
  - 対象は全 7K 譜面（MD5 の重複を除く）。前回までに解析した譜面（キャッシュ済み・再試行しない失敗）も解析済みに数える。
  - 残り時間は直近 30 秒の処理速度から求める（★の高い順に解析するため、開始からの平均では速度の変化に追いつかない）。
    測定が 3 秒に満たない間・処理が止まっている間は「計算中」。1 分以上は分単位に切り上げ、60 分以上は「時間・分」で表す。
  - ツールチップに説明と、解析できなかった譜面の件数（あれば）を出す。

| 対象 | フィルタ | ソート |

- ジャンル別の条件は範囲指定だけ（一致は選べない）。フィルタ画面では「比較条件」の下に「比較対象」のラベルとコンボボックスを出す。

- ジャンルごとの濃度・基準スキル値のソートはない。

## 7. 処理の流れ

1. DB 読み込み完了で `Analyze7kService.OnDatabaseLoaded()`。
2. キャッシュ（`cache/analyze-7k/results-{版}.jsonl`）を読み、`Beatmap.ChartAnalysis` に反映する。
3. 未解析の 7K 譜面を★の高い順に、16MiB スタック・優先度 BelowNormal の専用スレッドで解析する
   （並列数は既定で論理コア数の半分。`Analyze7kParallelism` で変更できる）。
   - .osu を読み、MD5 を照合し、ヘッダー（Mode 3・CircleSize 7・OD）を確認して `a7k_analyze` を呼ぶ。
     - osu!.db のフォルダ名の末尾に空白・ピリオドがあり、そのパスで見つからないときは、末尾を除いたフォルダ名でも探す
       （Windows はフォルダ作成時に末尾の空白・ピリオドを取り除くため。`Analyze7kRules.AlternateChartPath`）。
     - 先頭の `osu file format v` の前の空行・空白は読み飛ばす（osu! 本体と同じ。huuugeosu は BOM だけを読み飛ばす）。
   - 結果または失敗理由をキャッシュに追記する。ファイルなし・MD5 不一致・エンジンエラーは次回の起動で再試行する。
     - 再試行して前回と同じ理由で失敗したときは追記しない（起動のたびに同じ失敗の行が増えないように）。
     - ファイルが改行で終わっていない（書きかけの行で終了した）ときは、追記の前に改行を足す。

   失敗の主な理由（実データ 43,673 + 594 譜面、2026-11-14）:

   | 理由 | 譜面数 | 中身 |
   |---|---|---|
   | `not_7k` | 376 | ほぼすべて（374）がノーツ 0〜9 個の空の難易度で、段位エンジンが推定を返さない（`supported=false`、エンジンのメッセージは "only 7K supported"）。残り 2 は CircleSize 7.021 / 7.49 |
   | `md5_mismatch` | 214 | osu!.db の MD5 と .osu の中身が違う（osu! 側で譜面を再読み込みすれば解消） |
   | `file_missing` | 2 | フォルダ名の末尾の空白（上記の対応で読めるようになった） |
   | `engine_error` | 1 | ノーツの時刻が `NaN` の譜面 |
   | `invalid_file` | 1 | 先頭に空行がある譜面（上記の対応で読めるようになった） |
4. 3 秒ごとと完了時に結果を反映し、表示中のページを差し替える（7K 解析の条件・並びがあれば絞り込み直す）。

キャッシュのファイル名は「エンジン版（Prism / LN スキル / 上流コミット / アダプタ版）＋ C# の変換版（`chart-2`）」のハッシュ。
版が変わると古いファイルは削除され、全件を解析し直す。

## 8. ネイティブ API

```
a7k_analyze(osu, osu_len, request, request_len, out) -> status
  request: {"od": 8.0}
  out:     {"prism": {"overall", "ln", "genres": {Jumpstream, Handstream, Speed, Technical, JackSpeed, ChordjackOnly},
                      "tendency": {同じ6キー}},     // ジャンル傾向（§4.1）
            "dan": {"regular": {"raw_dan"}|null, "ln": {"raw_dan"}|null, "primary_family",
                    "eligible", "vibro", "bucketFeatures"}}
  7K 以外・段位エンジンの対象外の譜面は status 5 と {"error": "only 7K supported"}。
a7k_engine_version(out), a7k_free(buffer)
```

status: 0 OK / 1 引数不正 / 2 UTF-8 不正 / 3 要求不正 / 4 panic / 5 解析失敗（7K 以外など）。

## 9. 検証

§9.1〜9.3 は Jack を Jack / ChordJack に分ける前（5ジャンル、Jack = Chordjack）の版で測った結果。

### 9.1 旧実装との一致（2026-11-14）

MinaCalc を含む旧実装（`nakuru_mania_skill`、2026-11-13）で計算した実データの等速キャッシュ 43,673 譜面を正解として、
新しい `analyze_7k` の出力（`examples/probe.rs batch`、譜面の OD は旧キャッシュと同じ値）を比較した。

- **43,673 / 43,673 譜面で全項目が完全一致**（失敗 0 件）。
  比較項目: Reg / LN 段位、主分類、対象判定、縦連打判定、Prism の Overall・5ジャンル・LN、Reg / LN の段位ジャンル
  （段位ジャンルは huuugeosu の `mania_dan_buckets.py` で判定し直して比較）。
- 解析時間: 42,600 譜面を 12 スレッドで 569 秒。

### 9.2 ジャンル傾向・ジャンル濃度の分布（等速・43,673 譜面、2026-11-14）

ジャンル傾向を全ジャンル共通の物差し（§4.1）にした版（`analyze7k-3`）で、§9.1 と同じ譜面を解析し直した（12 スレッドで 620 秒）。

- 傾向以外の値（Overall・5ジャンルの基準スキル値・LN・段位推定・段位ジャンルの判定材料）は前の版と全譜面で一致。
- **全譜面で、1譜面の中の傾向の大小が基準スキル値の大小と一致**（基準スキル値が大きいのに傾向が大きくない組 0 件）。
  最大ジャンル（基準スキル値）と傾向が最大のジャンルも全譜面で一致。
- 各ジャンルの最大値は §4.1 の上限（理論値）と一致する。

ジャンル傾向:

| ジャンル | 10% | 25% | 中央値 | 75% | 90% | 最大 | 0（傾向なし）の割合 | 最大ジャンルになる割合 |
|---|---|---|---|---|---|---|---|---|
| Chordstream | 20.1 | 25.9 | 31.0 | 35.3 | 39.1 | 55.1 | 0.0% | 57.9% |
| Bracket | 0.3 | 4.1 | 10.6 | 18.1 | 26.0 | 43.5 | 7.9% | 7.5% |
| Delay | 1.3 | 8.8 | 18.5 | 25.5 | 31.2 | 73.4 | 4.5% | 5.0% |
| Technical | 1.9 | 6.0 | 13.8 | 24.8 | 35.2 | 59.5 | 1.5% | 11.7% |
| Jack | 2.6 | 8.7 | 16.6 | 25.7 | 38.3 | 84.7 | 5.2% | 17.9% |

ジャンル濃度（傾向の内訳。傾向の合計は 10% 点 65.0・中央値 97.2・90% 点 123.8・最大 177.5）:

| ジャンル | 10% | 中央値 | 90% | 最大 |
|---|---|---|---|---|
| Chordstream | 21.3% | 30.8% | 47.6% | 100.0% |
| Bracket | 0.4% | 10.8% | 26.6% | 99.9% |
| Delay | 1.9% | 18.5% | 28.7% | 58.1% |
| Technical | 2.3% | 15.0% | 32.9% | 72.9% |
| Jack | 3.2% | 16.7% | 39.2% | 100.0% |

- 前の版（ジャンルごとの上限 M で割っていた版）では、指数の大きい Delay の値が他より低く出て、Delay が最大になる譜面がなかった。
  共通の物差しにしたことで、最大ジャンルは基準スキル値と同じ判定になり、Delay も 5.0% の譜面で最大になる。
- ジャンルごとの濃度・基準スキル値のフィルタは §6 に追加した（ソートはない）。
